# Permission matrix

Checked against Microsoft Learn: 2026-10-11. Documentation verification is not tenant/runtime validation. Graph routes below are **v1.0**. No beta permission or endpoint is enabled by this design.

`D` = delegated; `A` = application. `V` = `/deviceManagement/virtualEndpoint`. Consent flags are taken from the [Graph permissions reference](https://learn.microsoft.com/en-us/graph/permissions-reference), not inferred from `.All`. A delegated scope never replaces the operator's Entra/workload role. Azure actions below are an action inventory, **not a verified deployable minimum custom-role definition**; validate exact operations against the Phase 1 artifacts and negative sandbox tests.

Identities: bootstrap = interactive customer administrator; operator = signed-in user (CLI or API OBO); API UAMI = operational storage/certificate access only; AVD UAMI = approved AVD execution; AVD observer UAMI = separate post-job resource observation; W365 UAMI = approved policy mutation; observer UAMI = separate W365 read-only execution. Mutation/observer identities must not share a read-only process. The bootstrap uses a reviewed local Graph client, never grants bootstrap scopes to the portal, and retains no vendor identity.

## Consent and activation

Bootstrap's broad D permissions belong only to its local administrative client/session. They are not runtime permissions and must not be copied into portal registrations. [Application/Cloud Application Administrator](https://learn.microsoft.com/en-us/entra/identity/enterprise-apps/grant-admin-consent) can manage customer applications and grant delegated consent, but cannot grant Microsoft Graph application roles in the baseline. Use Privileged Role Administrator (PRA), or Global Administrator (GA), for that step. Azure Owner is not a Graph consent role, and PRA is not an Azure resource deployment role.

AVD-only default: API selected D group discovery, optional D AVD SP lookup (omit if installation evidence suffices), Azure delegated `user_impersonation` for ARM; for dedicated named users, D `User.ReadBasic.All` and D `GroupMember.ReadWrite.All` (bounded by the operator's own group rights); **no AVD-worker Graph application grants**. The Azure delegated scope is not a Microsoft Graph permission. Pin and verify its resource registration/tool-client consent during bootstrap implementation.

Enable W365 only after additional consent review: API D `CloudPC.Read.All`, `LicenseAssignment.Read.All` and the existing D group-read scope; W365 UAMI A `CloudPC.ReadWrite.All`; separate observer UAMI A `CloudPC.Read.All`. Do not add Intune-wide configuration, user-write, licence-write or directory-write permissions merely because Windows 365 is managed through Intune. Authorised W365 operators also need suitable [workload RBAC](https://learn.microsoft.com/en-us/windows-365/enterprise/role-based-access).

## Verification gaps

- App-create documentation now lists `AppRegistration.Create` as least privileged, but its consent entry was not located in the fetched permission reference. Selected `Application.ReadWrite.All` is verified sufficient for the combined bootstrap, **not a claim of create-only minimum privilege**.
- Group-list documentation lists `Group-NestingSupport.ReadWrite.All` as its minimum, while its reference description concerns `disableNesting`. Member-list documentation lists `GroupMember.ReadBasic.All`, whose consent entry was not located. Select verified `GroupMember.Read.All`, a documented read alternative; true newest minimum/consent flags remain **unverified**. No write permission is granted for discovery.
- v1.0 member listing documents missing service-principal members. No beta workaround is enabled. Restrict provisioning targets to users and validate allowed group semantics before the W365 phase.
- [User `licenseDetails`](https://learn.microsoft.com/en-us/graph/api/user-list-licensedetails?view=graph-rest-1.0) is delegated-only despite A `LicenseAssignment.Read.All` existing for other routes. Require fresh operator evidence before queueing/assignment and pause stale jobs. App-only [user properties](https://learn.microsoft.com/en-us/graph/api/user-get?view=graph-rest-1.0) under `User.Read.All` are a broader possible alternative, **not approved or verified as an equivalent service-plan check**.
- [Cloud PC v1.0 schema](https://learn.microsoft.com/en-us/graph/api/resources/cloudpc?view=graph-rest-1.0) does not document `status`/`statusDetails`. Full lifecycle observation may need an additional verified v1.0 API or an explicit **beta** exception. Neither is selected here; resolve before W365 execution is enabled.
- Exact Azure action minima, constrained RBAC condition expressions, delegated reduced-permission preview, group/workload RBAC edge cases and installed-feature entitlement checks require sandbox validation. No live checks were performed in this session.
